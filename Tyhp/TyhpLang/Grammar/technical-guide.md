# TyhpLang Grammar — Developer Technical Guide

This guide covers the ANTLR `.g4` sources under `Tyhp/TyhpLang/Grammar/`: how the PHP, Tyhp, and tyhpdef grammars layer, how grammar addons work, how regeneration feeds the C# parsers, and the non-obvious conventions and traps you will hit when changing syntax.

**Scope of this directory:**

| File / artifact | Role | Consumed by |
|-----------------|------|-------------|
| `PhpLexer.g4` | Header plus `// #include "shared/PhpLexer.body.g4"` (modes, channels, PHP tokens); php-src **PHP-8.5.x** lineage | Expanded into the temp grammar dir; body included by both lexers |
| `PhpParser.g4` | Base PHP parser (LL rewrite of zend_language_parser.y, **PHP-8.5.x**); defines `*GrammarAddon` hooks; includes `shared/PhpParser.reached.g4` | `import PhpParser` from `TyhpParser.g4` |
| `TyhpLexer.g4` | PHP/Tyhp lexer entry. `tokens { }` then the PHP lexer body, tyhp-only keywords, and `shared/Tyhpdef.lexer-addons.g4` | `antlr-ng` entry for `.php` / `.tyhp` |
| `TyhpParser.g4` | PHP/Tyhp parser entry. `tokenVocab=TyhpLexer`, `import PhpParser`, Tyhp rules, and the tyhpdef rules `.tyhp` still names | `antlr-ng` entry for `.php` / `.tyhp` |
| `TyhpdefLexer.g4` | Tyhpdef lexer entry. Own `tokens { }`, PHP lexer body, tyhpdef keyword addons. No tyhp-only keyword rules | `antlr-ng` entry for `.tyhpdef` |
| `TyhpdefParser.g4` | Tyhpdef parser entry. `tokenVocab=TyhpdefLexer`. Includes the tyhpdef, Tyhp, override, and reached-PHP fragments | `antlr-ng` entry for `.tyhpdef` |
| `shared/*.g4` | Fragments. No `lexer grammar` / `parser grammar` header. Not passed to `antlr-ng` on their own | Expanded by `// #include` |
| `TyhpLexer.tokens` / `TyhpParser.tokens` | PHP/Tyhp token vocabulary. Integers in `TyhpLexer.tokens` are the PHP/Tyhp vocabulary | Regenerated by `compile_grammar.sh` |
| `TyhpdefLexer.tokens` / `TyhpdefParser.tokens` | Tyhpdef vocabulary. The same token name can have a different integer than in `TyhpLexer.tokens` | Regenerated by `compile_grammar.sh` |
| `*.interp` | Interpreter metadata for both grammars | Regenerated by `compile_grammar.sh` |
| `.antlr/` | Java artifacts from IDE / ANTLR tooling | Out of scope — not used by the Tyhp C# build; leave as-is |

Hand-written lexer/parser helpers and the generated C# recognizers live in `Tyhp/TyhpLang/Parser/`. This folder owns **syntax definition only**.

> Related: `Tyhp/TyhpLang/Parser/technical-guide.md` (generated C# + partials), `Tyhp/TyhpLang/Visitor/technical-guide.md` (parse tree → AST).

## 1. Role in the compiler pipeline

```
.g4 sources (this folder; // #include lines stay in the sources)
    → ./compile_grammar.sh
        → expand includes into a temp directory
        → antlr-ng on TyhpLexer / TyhpParser
        → antlr-ng on TyhpdefLexer / TyhpdefParser
        → compile_grammar_emit_partials.py
        → C# recognizers and visitor contracts in Parser/
    → .php / .tyhp: TyhpLexer / TyhpParser / TyhpParserAstVisitor
    → .tyhpdef: TyhpdefLexer / TyhpdefParser / TyhpdefParserAstVisitor
        → AST → Binder → Checker → Emitter
```

Editing a `.g4` file does **nothing** until you run `./compile_grammar.sh` from the repo root. `dotnet build` compiles whatever C# is already under `Parser/`; it does not regenerate from grammar.

## 2. File layout and import model

### Two entry grammars

`.php` and `.tyhp` are lexed and parsed with `TyhpLexer` / `TyhpParser`. `.tyhpdef` is lexed and parsed with `TyhpdefLexer` / `TyhpdefParser`. Shared rule text is a build-time include, not a second copy and not an ANTLR `import` of the lexer.

```
shared/PhpLexer.body.g4 ──include── TyhpLexer.g4          (.php / .tyhp)
                         └─include── TyhpdefLexer.g4       (.tyhpdef)

PhpParser.g4 ──import── TyhpParser.g4                     (.php / .tyhp)
                         tokenVocab=TyhpLexer

shared/Tyhpdef.rules.g4 ─┐
shared/Tyhp.reached.g4   ├─include── TyhpdefParser.g4     (.tyhpdef)
shared/TyhpOverrides…    │            tokenVocab=TyhpdefLexer
shared/PhpParser.reached ┘
         └─ #N parts also included from TyhpParser.g4 where .tyhp still names those rules
```

`// #include "shared/<file>.g4"` splices that fragment at the directive. A `#N` suffix (`shared/Tyhpdef.rules.g4#2`) splices only the Nth `// #part` slice (parts are 1-based; text before the first `// #part` is part 1). Sources keep the include lines. `compile_grammar.sh` expands them into a temp directory before `antlr-ng`.

`TyhpParser` still `import`s `PhpParser`, so the expanded `PhpParser.g4` has to sit in `--lib`. Tyhp still overrides an imported rule by defining the same name (see §4).

Lexer includes are merged before `antlr-ng`. Both lexer grammars include the PHP body, which already has `options`, `tokens`, and `channels`. The expand step concatenates the two `tokens` blocks (root grammar’s names first, then the PHP names), keeps one `options` block, and stitches rules that landed in the same mode so root-grammar rules stay ahead of the included body. That is what keeps `TyhpLexer.tokens` numbered the way the PHP/Tyhp vocabulary is numbered today. `TyhpdefLexer` is a different lexer, so its token integers may differ. PHP input is never lexed with `TyhpdefLexer`. Shared C# uses `TyhpParser.T_*` or `TyhpdefParser.T_*` — the constants of the parser that built the tree.

### What each entry contains

| Fragment | Contents |
|----------|----------|
| `shared/PhpLexer.body.g4` | PHP lexer after the `lexer grammar` line: channels, options, `tokens { }`, every mode and rule |
| `shared/PhpParser.reached.g4` | PHP rules the tyhpdef closure reaches, in `PhpParser.g4` order. `PhpParser.g4` also includes these parts and keeps the PHP file rules that closure does not reach |
| `shared/TyhpOverrides.reached.g4` | Tyhp override bodies the closure reaches |
| `shared/Tyhp.reached.g4` | Tyhp syntax the closure reaches that is not a `tyhpdef*` rule (generics, shapes, extensions, `type`, struct, and the rest) |
| `shared/Tyhpdef.rules.g4` | `tyhpdef*` rules the closure reaches, including `tyhpdefSrcFile`, `tyhpdefTaglessSrcFile`, and `tyhpdefBlock` |
| `shared/Tyhpdef.lexer-addons.g4` | Tyhpdef (and tyhp-or-tyhpdef) keyword rules and the `ST_TYHP_TAGLESS` `<?tyhpdef` alternatives, split with `// #part` |

`TyhpdefParser.g4` includes those four parser fragments and does not include the PHP file rules (`phpSrcFile`, `phpBlock`, `topStatement`, and the other unreached PHP roots) or the `.tyhp`-only rules (`tyhpSrcFile`, `tyhpBlock`, `tyhpTaglessSrcFile`, and the rest of that set).

`TyhpParser.g4` still includes the tyhpdef rules `.tyhp` object shapes reach: `tyhpdefDeprecatedOrObsolete`, `tyhpdefClassStatement`, and the class-body rules under them (`tyhpObjectShapeStatement` in `shared/Tyhp.reached.g4` calls `tyhpdefClassStatement`). It also still includes the file entries `tyhpdefSrcFile`, `tyhpdefTaglessSrcFile`, and `tyhpdefBlock`. Those entries stay because the shared visitor emit is one fragment per rule, compiled into both visitors; dropping the rule from `TyhpParser` would remove the `TyhpParser` context type those visit methods are written against. `.tyhpdef` files are not parsed with `TyhpParser`. `tyhpdefClassConstDecl` and `tyhpdefClassConstList` are unreached: they are written in `TyhpParser.g4` only and are not in `TyhpdefParser`.

`TyhpdefLexer.g4`’s `tokens { }` names the tyhpdef keywords and also names tyhp-only tokens that a shared parser alternative mentions (`T_TYHP_INTERNAL`, `T_TYHP_WITH`, `T_TYHP_USING`, `T_TYHP_TYPEOF`, `T_TYHP_NAMEOF`, `T_TYHP_VARIABLE_EXISTS`, `T_TYHP_USING_EQUAL`) with no lexer rule. The PHP body still contributes `T_NO_GRAMMAR_ADDON_0000`.

### Headers and options

- `TyhpLexer`: `lexer grammar TyhpLexer;`, `caseInsensitive = false`, `tokens { ... }` for Tyhp and tyhpdef token types (including `T_NO_GRAMMAR_ADDON_0000`), then the PHP lexer body via include.
- `TyhpdefLexer`: `lexer grammar TyhpdefLexer;`, its own `tokens { ... }`, then the same PHP lexer body and the tyhpdef lexer addons. No `<?tyhp` open-tag rules and no keywords whose predicate is `_languageMode == "tyhp"` only.
- `TyhpParser`: `parser grammar TyhpParser;`, `tokenVocab=TyhpLexer;`, `@header { #pragma warning disable CS3021 }`, then `import PhpParser;`.
- `TyhpdefParser`: `parser grammar TyhpdefParser;`, `tokenVocab=TyhpdefLexer;`, the same `@header`, then the includes listed above. It does not `import PhpParser`.
- `PhpLexer` / `PhpParser` document their PHP-src lineage (zend scanner / parser at **PHP-8.5.9**, LL rewrite of the LALR grammar). Prefer those header comments when wondering why a PHP construct looks the way it does.

### What this folder does *not* contain

- Generated C# (`TyhpLexer.cs`, `TyhpParser.cs`, `TyhpdefLexer.cs`, `TyhpdefParser.cs`, …) — under `Parser/`
- Hand-written semantic predicates / `NextToken` logic — `TyhpLexer.GrammarMethods.cs`, `TyhpParser.GrammarMethods.cs`. The `Tyhpdef*` GrammarMethods files are emitted from those partials.
- Visitor / AST types — `Visitor/`, `Ast/`

## 3. Regeneration: `compile_grammar.sh`

Grammar regeneration is **manual**. From the repo root, run:

```bash
./compile_grammar.sh
```

The script lives at the repository root (`compile_grammar.sh`). It is **not** wired into MSBuild / `dotnet build` / `tyhp.csproj`. Building the C# project compiles whatever generated sources already sit under `Parser/`; it never invokes `antlr-ng`.

### Requirements

- `antlr-ng` on `PATH` (`npm install -g antlr-ng`). The script exits if the command is missing.

### What the script does

1. `cd` to the repo root (directory containing the script).
2. Expand every `// #include "shared/<file>.g4"` (and `#N` part suffix) from `TyhpLexer.g4`, `TyhpParser.g4`, `PhpLexer.g4`, `PhpParser.g4`, `TyhpdefLexer.g4`, and `TyhpdefParser.g4` into a temp directory. Source `.g4` files are not overwritten. Lexer expansions are then merged (one `tokens` block, root-mode rules before the included body) before they are written.
3. **Tyhp lexer pass** — `antlr-ng` on the expanded `TyhpLexer.g4` into `Tyhp/TyhpLang/Parser/`, package `Tyhp.TyhpLang.Parser`, visitor on, listener off, `--lib` on the temp directory.
4. Move `*.tokens` / `*.interp` into `Grammar/` and copy `*.tokens` back into the temp directory so `tokenVocab=TyhpLexer` sees that vocabulary.
5. **Tyhp lexer + parser pass** — expanded `TyhpLexer.g4` and `TyhpParser.g4` together, same flags. Move `*.tokens` / `*.interp` into `Grammar/` again.
6. **Tyhpdef lexer pass**, then **tyhpdef lexer + parser pass**, same flags, on expanded `TyhpdefLexer.g4` / `TyhpdefParser.g4`. Each lexer pass runs first so `tokenVocab` reads a fresh `.tokens` file. `TyhpdefLexer.tokens`, `TyhpdefParser.tokens`, and the `.interp` files land in `Grammar/` beside the Tyhp ones.
7. Delete the temp directory.
8. Run `compile_grammar_emit_partials.py`. It writes `TyhpdefLexer.GrammarMethods.cs` and `TyhpdefParser.GrammarMethods.cs` from the Tyhp partials with the class name changed, and it writes the shared visit `.inc` fragments into both visitor hierarchies (`TyhpParser` / `TyhpLexer` renamed to `TyhpdefParser` / `TyhpdefLexer` on the tyhpdef side).

Flags on every `antlr-ng` invocation: `--define language=CSharp`, `--package Tyhp.TyhpLang.Parser`, `--generate-visitor true`, `--generate-listener false`, `--long-messages true`.

### Outputs

| Output | Location |
|--------|----------|
| `TyhpLexer` / `TyhpParser` / `TyhpdefLexer` / `TyhpdefParser`, each with a visitor interface and base visitor | `Tyhp/TyhpLang/Parser/` |
| `TyhpdefLexer.GrammarMethods.cs` / `TyhpdefParser.GrammarMethods.cs` (class rename of the Tyhp partials) | `Tyhp/TyhpLang/Parser/` |
| Shared visit partials (`*.Included.cs`) | `Tyhp/TyhpLang/Visitor/` |
| `*.tokens`, `*.interp` for both grammars | `Tyhp/TyhpLang/Grammar/` |

After regeneration: `dotnet clean && dotnet restore && dotnet build`, and update `Visitor/` / `Ast/` if new rules or labels need Visit methods or node types.

### `.antlr/` Java tree

IDE plugins or other ANTLR tooling may write Java under `Grammar/.antlr/` (e.g. `TyhpParser.java`, listeners). Those files are **out of scope** for the Tyhp C# toolchain: the compiler does not build them, and there is no owned regen/cleanup workflow for them. Leave them as-is. Do not hand-edit them expecting the C# toolchain to change. Regenerating C# is always via `./compile_grammar.sh`.

### Runtime vs generator version

NuGet: `Antlr4.Runtime.Standard` **4.13.1** (`tyhp.csproj`). Generated C# headers currently say **ANTLR Version: 4.13.2**. They work together in practice; keep the skew in mind when upgrading either side. Details and open questions also live in the Parser technical guide.

## 4. Grammar addon pattern

This is the core extension mechanism. Tyhp does **not** fork every PHP rule; it plugs into named hooks.

### How hooks are defined (`PhpParser.g4`)

Many rules include an alternative that calls a stub named `*GrammarAddon`. Default bodies match the placeholder token `T_NO_GRAMMAR_ADDON_0000` (declared in `TyhpLexer.g4` `tokens { ... }`; it is **not** a real lexeme). Comments say `// ! to be overridden in other grammars`.

`noGrammarAddon : T_NO_GRAMMAR_ADDON_0000;` exists so empty addon alternatives are not silently ε-productions.

Examples of hooks: `topStatementGrammarAddon`, `statementWithoutTerminalGrammarAddon`, `statementRequiringTerminalGrammarAddon`, `typeNameGrammarAddon`, `typeWithoutStaticGrammarAddon`, `phpExprBinaryOpGrammarAddon002`, `functionDeclarationStatementGrammarAddon`, `memberModifierGrammarAddon`, `internalFunctionsGrammarAddon`, plus many expression-operator slots (`phpExprUnaryPreOpsGrammarAddon`, numbered `phpExpr*OpGrammarAddon00N`, `phpExprPrecBaseGrammarAddon`, …).

### How Tyhp overrides

Tyhp redefines the same rule name. Override bodies the tyhpdef closure reaches live in `shared/TyhpOverrides.reached.g4` and are included by both `TyhpParser.g4` and `TyhpdefParser.g4`. Overrides are usually marked `// ! OVERRIDE`. Productions are almost always gated with a semantic predicate:

```antlr
{this.isLanguageMode("tyhp")}?
```

`isLanguageMode` is implemented on the hand-written `TyhpParser` partial (`TyhpParser.GrammarMethods.cs`) and compares against the parser’s `_languageMode` string.

Some overrides replace whole rules (not only addons), e.g. `phpTopExpr`, `forSyntax`, `newNonDereferenceable`, `optionalTypeWithoutStatic`, when the base alternative ordering or ambiguity cannot be fixed with an addon alone.

### Language mode strings

| Mode string | Typical source | Effect |
|-------------|----------------|--------|
| `"php"` / `"phpEcho"` | `<?php` / `<?=` open tags in `PhpLexer.g4` | PHP productions; Tyhp addons gated on `"tyhp"` stay off |
| `"tyhp"` | `<?tyhp` open tag / tagless Tyhp entry actions in `TyhpParser.g4` | Tyhp addon overrides active via `isLanguageMode("tyhp")` |
| `"tyhpdef"` | Lexer only. `<?tyhpdef` in `shared/Tyhpdef.lexer-addons.g4` sets lexer `_languageMode = "tyhpdef"` (included by both lexers) | Tyhpdef lexer keywords. The **parser** rules `tyhpdefBlock` and `tyhpdefTaglessSrcFile` assign parser `_languageMode = "tyhp"` (and copy it onto `_localctx._languageMode`). `PhpParserAstVisitor.GetCurrentLanguageMode` still returns `"tyhpdef"` for `TyhpdefParser.TyhpdefBlockContext` and `TyhpdefParser.TyhpdefTaglessFileContext`, and `""` for `TyhpdefParser.TyhpdefSrcFileContext` |

Lexer `_languageMode` and parser `_languageMode` are separate fields. `tyhpBlock` / `tyhpTaglessSrcFile` and `tyhpdefBlock` / `tyhpdefTaglessSrcFile` all assign parser `_languageMode = "tyhp"`. Tagless files pass `"tyhp"` or `"tyhpdef"` into `ConfigureTagless` on the lexer (`TyhpLexer` for `.tyhp`, `TyhpdefLexer` for `.tyhpdef`); that string is the lexer mode when the file has no open tag.

Tyhpdef-only contextual keywords (`partial`, `extern`, `omit`, `deprecated`, `obsolete`) are **not** GrammarAddon overrides. They lex as `T_STRING` and `NextToken` reclassifies them, so a member named `partial` or `extern` stays `T_STRING`. See §5.

## 5. Lexer: PHP base + Tyhp extensions

### PHP base (`PhpLexer.g4`)

- Channels: `DocBlockCommentsChannel`, `SimpleCommentsChannel`, `WhiteSpaceChannel`, `ErrorLexemChannel`, `SkipChannel`, `StubTokenChannel`.
- Modes include `ST_INLINE_HTML`, `ST_IN_SCRIPTING`, `ST_LOOKING_FOR_PROPERTY`, string/heredoc/nowdoc modes, `ST_VAR_OFFSET`, etc.
- Modes that can dead-end on unexpected input carry a one-char catch-all that emits `T_ERROR` and `popMode`s (`ST_LOOKING_FOR_PROPERTY_INVALID`, `ST_VAR_OFFSET_INVALID`). Without those, ANTLR's default lexer recovery stays in the dead-end mode and the rest of the file is lexed as spurious errors. `ST_VAR_OFFSET_INVALID` hides the token on `ErrorLexemChannel` (safe there — `]` still terminates the array-offset expression on the default channel). `ST_LOOKING_FOR_PROPERTY_INVALID` keeps the token on the **default channel** instead: `memberName` has no `T_ERROR` alternative, so hiding it would let the parser silently splice the next real tokens into the member-access expression (e.g. `$x->;` followed by `$y = 1;` reparsing as `$x->$y = 1;` with zero diagnostics). Keeping it visible forces one clean, local `TYHP1002` at the actual error site.
- Open tags: `<?php` / `<?=` set language mode and push `ST_IN_SCRIPTING`. Bare `<?` uses `CHECK_FOR_OTHER_OPEN_TAGS` → `more, pushMode(ST_CHECK_FOR_OTHER_OPEN_TAGS_LEXER_ADDON)`.
- `//` and `#` comments stop before `?>` (`lineCommentExcludesCloseTag` on the newline and end-of-file rules). The closer stays available so the following template is lexed as inline HTML.
- Default body of that addon mode in PHP is a catch-all error (`VIRTUAL_ST_CHECK_FOR_OTHER_OPEN_TAGS`). Both entry lexers replace that mode: `TyhpLexer` recognizes `tyhp` and `tyhpdef`; `TyhpdefLexer` recognizes `tyhpdef` (the `<?tyhp` alternatives stay on `TyhpLexer` only).

### Tyhp lexer additions (`TyhpLexer.g4` and `TyhpdefLexer.g4`)

Both lexers include `shared/PhpLexer.body.g4` (all of its modes) and `shared/Tyhpdef.lexer-addons.g4`. Channels are the same six names, in the same order, so `DocBlockCommentsChannel` is channel 2 on both. Token type integers are not shared: `TyhpLexer.tokens` is the PHP/Tyhp vocabulary; `TyhpdefLexer.tokens` numbers its own `tokens { }` block first.

**Tokens block** — Tyhp-only token types (`T_TYHP_OPEN_TAG`, `T_TYHPDEF_OPEN_TAG`, `T_TYHP_ASYNC`, `T_TYHP_INTERNAL`, `T_TYHP_USING`, `T_TYHP_IS`, `T_TYHP_USING_EQUAL`, `T_DECIMAL_CAST`, …) plus `T_NO_GRAMMAR_ADDON_0000`. `struct` has no dedicated token (same as `object`): it is always `T_STRING`.

**`ST_CHECK_FOR_OTHER_OPEN_TAGS_LEXER_ADDON`** — after `<?`, recognize `tyhp` / `tyhpdef` (with whitespace / EOF variants), set lexer `_languageMode`, emit the Tyhp open-tag token type, and enter `ST_IN_SCRIPTING`.

**`ST_IN_SCRIPTING` overrides** — contextual keywords lex as `T_STRING` (no language-mode predicate on the rule). `NextToken` reclassifies that token from `_languageMode` and the spelling. Lookahead skips whitespace and comments, and the token text stays the keyword. Examples:

- Shared Tyhp+tyhpdef, fully contextual `T_STRING` (no dedicated lexer token; parser predicates decide keyword vs name): `struct` (same pattern as `object`)
- Shared Tyhp+tyhpdef, lookahead-contextual (reclassified in `NextToken`): `type`, `extension`, `async` (keyword only before `function` / `fn` / a member modifier / `{`), `operator` (keyword only before an operator token including `=` for `==`/`===` / `empty` / `convert`), `void` (keyword unless the next token is `(` or `<`, so `function void()` stays an identifier)
- Shared Tyhp+tyhpdef, unconditional: `await`, `parent` (`parent` cannot use the `void` `(`-fallback — both `: parent(...)` ctor returns and `function parent()` are followed by `(`. Identifier uses go through `nameTokenValueGrammarAddon` / `semiReserved`)
- Shared Tyhp+tyhpdef, other: `(decimal)` cast
- tyhpdef-only, lookahead-contextual (reclassified in `NextToken`, so a real
  member/function named `partial`, `extern`, `omit`, `deprecated`, or `obsolete` still parses): `partial` (keyword only immediately
  before `class`/`trait`/`interface`/`enum`), `extern` (keyword only immediately before `class`/`interface`/`enum`/`function`/`const` **or** a type name — identifier or `\`-qualified FQCN — and not in `.tyhp` mode), `omit` / `deprecated` / `obsolete` (keyword only immediately before the start of
  a declaration — an identifier, `\`-qualified name, or `?`-nullable type; not before `extends` /
  `implements`, which means the word itself is being used as a name there)
- Tyhp-only: `internal` (hard keyword in `_languageMode == "tyhp"` only — not PHP, not tyhpdef; identifier uses go through `nameTokenValueGrammarAddon` / `tyhpSemiReserved`), `with`, `using`, `is`, `typeof`, `nameof`, `variable_exists`, `:=`

**`ST_TYHP_TAGLESS`** — used when `source.tagless` is enabled and the file starts with a literal open tag. `ConfigureTagless` lives on `TyhpLexer.GrammarMethods.cs` and is emitted onto `TyhpdefLexer` by `compile_grammar_emit_partials.py` (class rename only). `.tyhpdef` tagless files call it on `TyhpdefLexer` with language mode `"tyhpdef"`. The mode consumes optional `<?tyhp` (`TyhpLexer` only) or `<?tyhpdef` (both lexers), then switches to `ST_IN_SCRIPTING`. No path back to inline HTML; closing `?>` is rejected by the tagless **parser** entry rules (they omit `T_CLOSE_TAG`). If there is no open tag, ConfigureTagless starts directly in `ST_IN_SCRIPTING` so line/column tracking stays correct.

Tyhp-only keyword rules (`internal`, `with`, `using`, `typeof`, `nameof`, `variable_exists`, `:=`, and the `<?tyhp` open tags) are written in `TyhpLexer.g4` and are not included by `TyhpdefLexer`.

Actions called from `.g4` (`prepareLess`, `doPreparedLess`, `streamLA`, `closeTagHandler`, …) are implemented in the Tyhp lexer partial and emitted onto `TyhpdefLexer` — edit the Tyhp partial, then regenerate.

## 6. Parser: entry points and Tyhp surface

### Entry rules

`.php` and `.tyhp` call these on `TyhpParser`. `.tyhpdef` calls the tyhpdef entries on `TyhpdefParser` (`CompilationService`, `Tyhpdef.ParseContent`, CLI). The same tyhpdef entry rules are also included into `TyhpParser`; that copy is what the shared visitor fragment is typed against, and it is not the parser `.tyhpdef` files use.

| Rule | Parser that walks the file | Use |
|------|----------------------------|-----|
| `phpSrcFile` | `TyhpParser` (imported from `PhpParser`) | `.php` |
| `tyhpSrcFile` | `TyhpParser` | Tagged `.tyhp` (`<?tyhp` … optional close tags / inline output) |
| `tyhpTaglessSrcFile` | `TyhpParser` | Tagless `.tyhp`; optional `T_TYHP_OPEN_TAG`; no inline HTML / close tag. Leading action sets parser `_languageMode = "tyhp"` |
| `tyhpdefSrcFile` | `TyhpdefParser` | Tagged `.tyhpdef` |
| `tyhpdefTaglessSrcFile` | `TyhpdefParser` | Tagless `.tyhpdef`; optional `T_TYHPDEF_OPEN_TAG`. Leading action sets parser `_languageMode = "tyhp"` |
| `tyhpdefBlock` | reached from `tyhpdefSrcFile` | Sets parser `_languageMode = "tyhp"` after `T_TYHPDEF_OPEN_TAG` |

### Tyhpdef-specific rules

Dedicated regions cover tyhpdef top statements, import forms for functions/classes/traits/interfaces/enums, typed consts/variables with optional `deprecated`/`obsolete`, class member imports, thin class-body `extension fn` / `extension operator` mappings, aliases, etc. These are first-class TyhpParser rules (not only addons).

Current tyhpdef extras (Story 20):

- **`global use` / `global use function` / `global use const` / `global use extension`** — compilation-wide imports (C# `global using`, not PHP `global $var`). Same shapes exist on `.tyhp` via `topStatementGrammarAddon`.
- **`partial`** — lexer token `T_TYHPDEF_PARTIAL` (lexer `_languageMode == "tyhpdef"` **and** `streamLA` sees `class`/`trait`/`interface`/`enum`/`function` next; otherwise it lexes as plain `T_STRING`, e.g. a method named `partial`). Optional on tyhpdef `class` / `enum` / `interface` / `trait` brace headers. Overlay header-only: `partial class Foo<T> implements …;` (`IsPartial` required, ends in `;`, no body). Name-only overlay merge: `partial function foo;` / `partial function foo as bar;` / class-body `partial function format;` (`tyhpdefPartialFunctionDeclarationStatement`, `#tyhpdefPartialClassMethod`). No parameter list, return type, generics, `async`, visibility, or `omit` on the same declaration — those are parse failures, not a full-replace recovery. Optional `as` alias is a Tyhp-name keep/rename (see binder).
- **`extern`** — lexer token `T_TYHPDEF_EXTERN` (same tyhpdef-only reclassification as `omit`: `_languageMode == "tyhpdef"` **and** the next non-comment character is a letter or `\` — including `class`/`interface`/`enum`/`function`/`const` and a type name; otherwise `T_STRING`, e.g. a method named `extern`). Not a keyword in `.tyhp` mode. Bodyless name-only form: `extern class \Foo\Bar;` / `extern interface I;` / `extern enum E;` / `extern function \bcadd;` / `extern const \FOO;` / kind-unspecified `extern \Foo\Bar;` (`tyhpdefExternClassDeclarationStatement`, `tyhpdefExternInterfaceDeclarationStatement`, `tyhpdefExternEnumDeclarationStatement`, `tyhpdefExternFunctionDeclarationStatement`, `tyhpdefExternConstDeclarationStatement`, `tyhpdefExternDeclarationStatement`), wired as the first alternatives of `tyhpdefAttributedStatement` (`#tyhpdefExternClassDecl` / `#tyhpdefExternInterfaceDecl` / `#tyhpdefExternEnumDecl` / `#tyhpdefExternFunctionDecl` / `#tyhpdefExternConstDecl` / `#tyhpdefExternDecl`). Function/const alternatives sit before the bare form so `function` / `const` are not eaten as a `name`. Identifier is `name` (FQCN and qualified names). PHP’s contextual `enum` keyword is `T_ENUM` when the next non-comment character is an identifier start or `\`, so `extern enum \Foo\Bar;` tokenizes `T_ENUM`. A namespace segment `enum\Foo` (no whitespace before `\`) stays a qualified name. No body, members, generics, `extends` / `implements`, enum backing type, `abstract` / `final` / `readonly`, `as` alias, signature/value, or `tyhpdefDeprecatedOrObsolete` / `partial` on the same declaration — those are parse failures, not a class-with-body / signed-function recovery. `extern class Name { … }` and `extern class Name extends/implements/as/<…>;` are explicit extra alternatives of `tyhpdefExternClassDeclarationStatement` that consume the illegal tokens and call `reportExternClassCannotHaveBody()` so ANTLR does not recover by deleting `extern` into `tyhpdefImportClassDeclarationStatement`. Optional `// @provided-by: tyhpdef/…` immediately above the declaration is a **comment** parsed by the visitor (`FindPossibleProvidedBy`); it is not a grammar production.
- **`fallback`** — lexer token `T_TYHP_FALLBACK` (shared by `.tyhp` and `.tyhpdef`; reclassified from `T_STRING` only when `function`, `async`, or `const` is the next word, so a function named `fallback` stays `T_STRING`). Optional on `tyhpdefImportFunctionDeclarationStatement` and `tyhpdefImportConstStatement`. Not legal on classes. Binder resolution is in `TyhpBinder.Fallback.cs`. `declare(ext="name")` / `declare(ext="!name")` is the same `declare` statement as `declare(php=…)`, with key `ext`.
  In Tyhp mode the same token marks a `fallback` declaration: the lexer reclassifies `fallback` (`FallbackDeclarationAhead`) when `function`, `async`, `const`, `class`, `interface`, `trait`, `enum`, or a class modifier follows. `topStatementGrammarAddon` (`#tyhpFallbackDecl` around `attributedStatement`, `#tyhpFallbackConstDecl` for `fallback const …;`) and `innerStatementGrammarAddon` (`#tyhpInnerFallbackDecl`) accept it. The visitor marks the AST with `FallbackDeclaration.MarkFallback` (grammar addon key `isFallback`); the emitter wraps the declaration in the existence check.
- **`omit`** — lexer token `T_TYHPDEF_OMIT` (same tyhpdef-only mode, same `streamLA` contextual gating — keyword only immediately before the start of a declaration, so a member/function named `omit` still lexes as `T_STRING`). Shares the `tyhpdefDeprecatedOrObsolete` slot with `deprecated` / `obsolete` (those two use the same lookahead). Skeleton forms (`omit function \array_map();`, `omit class \Closure {};`, `omit public function getPrevious();`) parse because `parameterList`, `returnType`, and `tyhpdefClassStatementList` are already empty-capable. Tyhpdef function/class/trait/interface/enum import names use `name` (so a leading `\` FQN is legal), matching documented `function \strlen(...)` / overlay `omit` skeletons. Function names still accept `semiReserved` as a third alternative, including optional generic parameters (`function catch<TResult>(...)`). Tyhpdef class-const / member identifiers (`tyhpdefIdentifierWithOptionalAlias`) also accept `semiReserved`, so PHP reserved words used as constant names (`public const int MATCH`) parse.
- **Standalone `extension Name { }`** — `tyhpdefStandaloneExtensionDeclarationStatement`. Same block target as live Tyhp: optional `tyhpGenericParameterDeclarations` on the name, then optional header `extends typeExprWithoutStatic`. The `extends` inside a generic constraint stays inside `<…>`; the header `extends` is the target. Nested `extends Type { }` / `extends<T> Type { }` groups are one level (`tyhpdefStandaloneExtensionTargetGroup`); a group's body is short members only. Members are short `fn` / `operator` with `=>` (`tyhpExtensionCallableParameters`; `$this` implied; optional leading `&$this`). Short function members use `fn` only (not `function`). Optional `attributes?` on the `tyhpdefTopStatement` alternative so `#[\Tyhp\Php]` can be diagnosed (4304) rather than rejected at parse. Optional `attributes?` on members for `#[\Tyhp\Optimize\Pure]` (not `#[Inline]` — TYHP4176). `tyhpExtensionCallableParameters` / `tyhpExtensionOperatorLegacyTarget` match the per-member target spellings so the visitor can report TYHP4361 (use the block form) instead of an unexpected-token error.
- **Tyhpdef `declare`** — `tyhpdefStatement` `#tyhpdefDeclare` takes `tyhpdefDeclareBody`: file-level `;`, `{ tyhpdefTopStatementList }`, or colon/`enddeclare` with tyhpdef statements (not PHP `innerStatementList`). `.tyhp` file-level / block declare is unchanged. Member/type `#[\Tyhp\Php]` still rides `tyhpdefAttributedTopStatement` and class-body attribute slots.
- **`#[\Tyhp\Php]` on Tyhp `extension`** — optional `attributes?` on `topStatementGrammarAddon` alt `#tyhpExtensionDecl`. The binder reports 4304; gating those declarations uses `declare(php=…) { }`. `innerStatementGrammarAddon` `#tyhpInnerExtensionDecl` lets `extension` appear inside a Tyhp `declare(...) { }` body. `#tyhpInnerTypeAliasDecl` is the same slot for a `type` alias (optional attributes and `internal`, including `type Name = struct { }`), so a declare block can gate a struct the way it gates an extension.
- **Attributes on class-body** `extension fn` / `extension operator` (`attributes?` on those `tyhpdefClassStatement` alts) for owned-type `#[\Tyhp\Optimize\Inline]`.
- **Thin class-body extension mappings** — `tyhpdefExtensionFunction` is `extension fn … => expr;` only (no `extension function`, no brace `methodBody`). `tyhpdefExtensionOperator` is bodyless `extension operator …;` (checker TYHP8013) or `extension operator … => expr;`. A brace after either is a parse error. Standalone tyhpdef `extension Name { fn … => …; }` and Tyhp `extension { fn … => …; }` / `{ function … { … } }` are separate rules and still allow their own forms.
- **Bodyless hooked properties** — `#tyhpdefClassPropertyAccessors` is a second property alternative on `tyhpdefClassStatement` (class / interface / trait / enum bodies). Shape is one `$name` plus `{ get; set; }` hooks. See [Tyhpdef hooked properties](#tyhpdef-hooked-properties).
- **`use extension` adaptations** — postfix contextual `hide` (`traitAliasGrammarAddon` + `isHideKeyword`); `operator` + token + optional `<Type>` via `traitMethodReferenceGrammarAddon` / `absoluteTraitMethodReferenceGrammarAddon` (PHP identifier alts stay on the original rules); `insteadof` uses those refs. `hide` is not a lexer keyword.

`tyhpdefBlock` and `tyhpdefTaglessSrcFile` assign parser `_languageMode = "tyhp"` (and `_localctx._languageMode`) so Tyhp GrammarAddon predicates (including `hide`) fire. Lexer `_languageMode` on `<?tyhpdef` is `"tyhpdef"`, so `partial` / `extern` / `deprecated` / `obsolete` / `omit` tokenize (each is `streamLA`-contextual, so a member named one of those words is still `T_STRING`). `PhpParserAstVisitor.GetCurrentLanguageMode` returns `"tyhpdef"` when it sees `TyhpdefParser.TyhpdefBlockContext` or `TyhpdefParser.TyhpdefTaglessFileContext`, and `""` when it sees `TyhpdefParser.TyhpdefSrcFileContext`. The tyhpdef walk calls `TyhpdefIncludedPhpVisits.GetCurrentLanguageMode`, which returns those same three strings for those same `TyhpdefParser` contexts.

### Semantic predicates implemented in C#

Grammar actions that need non-trivial lookahead call methods on `TyhpParser`:

- `isLanguageMode(string)`
- `isHideKeyword(IToken)` — contextual `hide` inside `use extension { … }` adaptations (`T_STRING` spelling only; `function hide()` elsewhere stays an identifier)
- `isObjectKeyword(IToken)` — PHP `object` type spelling (`T_STRING` only; there is no `T_OBJECT` token)
- `isStructKeyword(IToken)` — contextual `struct` spelling (`T_STRING` only; there is no `T_TYHP_STRUCT` token)
- `looksLikeObjectShape()` — `object {` on a `type` alias RHS vs bare `object` / `object extends`
- `looksLikeObjectShapeIntersection()` — alias-RHS intersection with at least one `object { … }` item
- `looksLikeStructShape()` — type-position `struct {` / `struct extends` vs a named `struct Point` (no longer a declaration) or a class/type named `struct`. Also gates the first `typeWithoutStatic` alternative so SLL does not parse `struct` as a type name when `{` / `extends` follows
- `looksLikeAnonymousStruct()` — `new struct { … }` / `new struct() { … }` / `new struct extends T { … }` vs `new struct()` / `new struct;` constructing a class named `struct`
- `callableIsFollowedByOpenParen()` — `callable (` or `callable` plus a PHP builtin-cast token (`(int)` / `(string)` / …) vs bare `callable`
- `callableShapeDefaultIsPresent()` — `=` on a callable-shape parameter is followed by an `expr`, not `)` / `,`
- `looksLikeGenericTypedLocal()` — distinguishes `Box<int> $x` from `(Box < int) > $x`
- `looksLikeTypedConstDecl()` — distinguishes file-level `const int X = 1` from `const FOO = 1`
- `newIsFollowedByArgumentList()` — distinguishes `new X<T>(args)` from comparison chains
- `reportExternClassCannotHaveBody()` — syntax error action for `extern class Name { … }` (not a predicate; keeps recovery off `class Name { … }`)

Those live in `TyhpParser.GrammarMethods.cs`. If you add a new `{this.foo()}?` in a `.g4`, implement `foo` on that partial before regenerating (or regen will produce calls that do not compile).

## 7. Notable PHP base productions (`PhpParser.g4`)

These rules live in the PHP base parser (not Tyhp addons). They matter when aligning with php-src or when visitors / emitters assume a particular shape.

### Parameters (`attributedParameter`)

`parameterList` is a comma-separated list of `attributedParameter` (`Attributes=attributes? Parameter=parameter`). That is how methods, functions, closures, and property-hook parameters accept `#[…]` before a parameter.

Tyhp operator-overload productions do **not** go through `parameterList` (they are a fixed left / optional-right operand pair). Their operand slots still use `attributedParameter`:

- `tyhpClassOperatorOverload`
- `tyhpExtensionOperatorOverload`
- `tyhpdefClassOperator`
- `tyhpdefExtensionOperator`
- `tyhpdefStandaloneExtensionOperatorDecl`

`#[…]` immediately before an operand is therefore legal. The visitor copies those attributes onto `PhpParameterAst` via `VisitAttributedParameter` (same path as method parameters). Bare `parameter` would reject `T_ATTRIBUTE` at parse.

### Property hooks

`hookedProperty` opens a `{ … }` hook list via `propertyHookList`. Each item is a `propertyHook`:

```antlr
propertyHook
    : Attributes=attributes? Modifiers=propertyHookModifiers ReturnsRef=returnsRef
        AccessorName=T_STRING Parameters=optionalParameterList
        AccessorBody=propertyHookBody
    ;
```

- **`attributes?`** — zero or more `#[…]` attribute groups may precede each hook (same `attributes` rule used elsewhere). Attributes attach to that hook, matching php-src `property_hook_list`.
- **`propertyHookList`** — `Items+=propertyHook*` (no separator token between hooks).

`propertyHookBody` alternatives:

| Form | Shape | Typical use |
|------|--------|-------------|
| Block | `{` `innerStatementList` `}` | Concrete get/set body |
| Expression | `=>` `expr` `;` | Expression-bodied hook |
| Bare semicolon | `;` | Abstract / interface hooks (`{ get; set; }`), matching php-src `property_hook_body` |
| Addon | `propertyHookBodyGrammarAddon` | Tyhp extension stub (`T_NO_GRAMMAR_ADDON_0000` by default) |

Tyhp `.tyhp` / PHP files use this `hookedProperty` surface (bodies allowed). Tyhpdef uses a **separate** bodyless rule — do not reuse `hookedProperty` there. See [Tyhpdef hooked properties](#tyhpdef-hooked-properties).

**Emit rewrite** (see Emitter §6 / §6f): hooks themselves are native ≥ 8.4 and polyfilled &lt; 8.4.
Attributes on hooks follow the same gate:

| Source | ≥ 8.4 | &lt; 8.4 (polyfill) |
| --- | --- | --- |
| `{ #[Attr] get { … } }` | inline `#[…]` in hook block | strip `#[…]` + TYHP5017; hook body → polyfill methods |

### Tyhpdef hooked properties

Tyhpdef class / interface / trait / enum members use `tyhpdefClassStatement`. Unhooked properties stay `#tyhpdefClassProperty` (`type $a, $b;`). Optional `?? expr` on each `tyhpdefProperty` is the expected PHP start value (same form as tyhpdef consts; not `=`). Hooked properties are a **separate** alternative so a hook list cannot attach to a comma list:

```antlr
tyhpdefClassStatement
    : … propertyModifiers typeExprWithoutStatic tyhpdefPropertyList T_SYM_SEMICOLON
        #tyhpdefClassProperty
    | … propertyModifiers typeExprWithoutStatic tyhpdefHookedProperty
        #tyhpdefClassPropertyAccessors
    | …
    ;

tyhpdefProperty
    : Variable=T_VARIABLE (T_COALESCE CoalesceExpr=expr)?
    ;

tyhpdefHookedProperty
    : Variable=T_VARIABLE (T_COALESCE CoalesceExpr=expr)? T_OPEN_CURLY_BRACE
        Accessors=tyhpdefPropertyHookList T_CLOSE_CURLY_BRACE
    ;

tyhpdefPropertyHookList
    : Items+=tyhpdefPropertyHook+
    ;

tyhpdefPropertyHook
    : Attributes=attributes? Modifiers=propertyHookModifiers ReturnsRef=returnsRef
        Identifier=identifier T_SYM_SEMICOLON
    ;
```

Contract:

- **Bodyless only** — each hook is `get;` / `set;` (optional `&` via `returnsRef`, optional `propertyHookModifiers`, optional `attributes`). Brace bodies (`get { … }`) and expression bodies (`get => …;`) do not parse.
- **One name** — `public int $a, $b { get; }` does not parse. Unhooked `public int $a, $b;` still does.
- **Non-empty list** — `{ }` is a parse error (`+`, not `*`).
- **Expected default** — optional `?? expr` before `{`, matching PHP `= expr { hooks }` with tyhpdef `??` instead of `=`. Unhooked properties take the same `??` on `tyhpdefProperty`. Tyhpdef consts (global and class) are `??` only; `=` is illegal in `.tyhpdef`. Parameter defaults stay `=`.
- **Do not reuse PHP `hookedProperty`** — that rule allows bodies and `= default { hooks }`.
- **Structs** — `tyhpStructProperty` has no hook list (and keeps PHP `=` defaults via `property`).
- **Tyhp `.tyhp`** — still uses PHP `hookedProperty` / `propertyHookBody` (bodies unchanged). class-const `=` in `.tyhp` is unchanged.

`propertyHookModifiers`, `returnsRef`, and `attributes` are the PHP-base productions. `&set` is not a parse error (same as PHP/Tyhp: parse, then check).

The visitor maps `#tyhpdefClassPropertyAccessors` onto the same `PhpPropertyAst.Hooks` path as PHP `#classPropertyAccessors` (bodyless hooks).

### `exit` / `die` (`#phpExprExit`)

In `phpExprBase`:

```antlr
| T_EXIT ArgumentList=argumentList?                                         #phpExprExit
```

- Lexer token is **`T_EXIT`** for both `exit` and `die` (not `T_STRING`), so call forms cannot fall through the normal function-call path.
- Optional **`argumentList`** is the same production used by calls / `ctorArguments` (php-src `ctor_arguments` shape): parentheses required when present; empty `()`, positional / named args, trailing comma via `possibleComma`, or `...` first-class callable.
- Bare `exit` / `die` with no `argumentList` remains valid (statement or expression without call parens).

`argumentList` itself:

```antlr
argumentList
    : T_OPEN_ROUND_BRACE
        (
            (ArgumentList=nonEmptyArgumentList possibleComma)
            | Ellipsis=T_ELLIPSIS // first class callable
        )?
        T_CLOSE_ROUND_BRACE
    ;
```

**Emit rewrite** (`BuildExitDieExpression`, Emitter §6e). Gate: `IsPhpVersionAtLeast(8, 4)`.

| Source | ≥ 8.4 (native) | &lt; 8.4 (lowered) |
| --- | --- | --- |
| `exit;` / `die;` | unchanged | unchanged |
| `exit($status)` / `die($status)` | unchanged | unchanged |
| `exit()` / `die()` | empty call spelling | bare `exit` / `die` |
| `exit(status: $s)` | named call | `exit($s)` |
| `exit(...)` FCC | `exit(...)` | `(static fn(string\|int $status = 0) => exit($status))` |

### `clone` — unary vs call (`#phpExprClone` / `#phpExprCloneCall`)

In `phpExprPrec` (same precedence band; call alternative listed first):

```antlr
| Op=T_CLONE ArgumentList=cloneArgumentList                                 #phpExprCloneCall
| Op=T_CLONE R=phpExprPrec                                                  #phpExprClone
```

Matches php-src `clone_argument_list` ambiguity handling:

| Source | Parse form | AST (hybrid model) |
|--------|------------|--------------------|
| `clone $x` | unary `#phpExprClone` | `PhpUnaryOpAst` + expression operand |
| `clone($x)` / `clone ($x)` | unary + parenthesized expr (not a call list) | same unary AST |
| `clone()` | `#phpExprCloneCall` empty list | unary op + empty `PhpArgumentListAst` |
| `clone($x,)` | call (trailing comma disambiguates) | unary op + 1-arg list |
| `clone($x, $with)` | call (multi-arg) | unary op + arg list |
| `clone(...)` | call FCC via `cloneArgumentNoExpr` | unary op + variadic placeholder arg |
| `clone(object: $x)` / `clone(...$arr)` | call (named / unpack first) | unary op + arg list |

`cloneArgumentList` never matches bare `'(' expr ')'` — that forces `clone($x)` through the unary production. Binder attaches ExtCore tyhpdef symbols to call-shaped forms only; unary stays on the object-type check.

**Emit rewrite** (`BuildCloneExpression` + `WithKeywordHelper`, Emitter §6d). Gate: `IsPhpVersionAtLeast(8, 5)`.

| Source | ≥ 8.5 (native) | &lt; 8.5 (lowered) |
| --- | --- | --- |
| `clone $x` / `clone($x)` (unary) | unchanged | unchanged |
| `clone($o,)` / `clone(object: $o)` | call spelling | `clone $o` |
| `clone($o, […])` / named withProperties | call spelling | `\Tyhp\ObjectHelper::with(clone $o, …)` |
| `clone(...)` FCC | `clone(...)` | static arrow wrapping ObjectHelper |

### Removed: `(unset)` cast

`(unset)` / `T_UNSET_CAST` is **not** part of Tyhp’s PHP grammar. PHP 8.5 deprecates the cast (and PHP will remove it), and Tyhp’s highest supported PHP is 8.5 — so the lexer token and rule are omitted entirely. `(unset)$x` does not lex as a cast and is rejected. Prefer `null` / `default(null)` instead of the old unset cast.

### Pipe operator `|>` (`#phpExprPipe`)

In `phpExprPrec` (left-associative binary; ANTLR earlier alternatives bind tighter):

```antlr
| L=phpExprPrec Op=phpExprBinaryConcatOps R=phpExprPrec                     #phpExprBinaryConcat
| L=phpExprPrec Op=T_PIPE R=phpExprPrec                                     #phpExprPipe
| L=phpExprPrec Op=phpExprCompareSizeOps R=phpExprPrec                      #phpExprCompareSize
```

- Lexer token is **`T_PIPE`** (`|>`), distinct from bitwise **`T_SYM_PIPE`** (`|`).
- Precedence matches php-src (`%left T_PIPE` between `.` and comparison): after concat / arithmetic / shift, before comparison / equality / bitwise / boolean / `??` / ternary / assignment.
- Visitor builds a normal `PhpBinaryOpAst` with operator token `T_PIPE` (`PhpBinaryOperator.Pipe`). Checker requires a single-arg callable RHS (TYHP4162–4164).

**Emit rewrite** (`BuildPipeExpression`, Emitter §6b). Gate: `IsPhpVersionAtLeast(8, 5)`.

| Source | ≥ 8.5 (native) | &lt; 8.5 (lowered) |
| --- | --- | --- |
| `$a \|\> foo(...)` | `$a \|\> foo(...)` | `foo($a)` (FCC unwrap) |
| `$a \|\> f(...) \|\> g(...)` | native chain | `g(f($a))` |
| `$a \|\> (fn($x) => …)` | RHS parenthesized | `(fn($x) => …)($a)` |
| `$a \|\> $callable` | `$a \|\> $callable` | `$callable($a)` |

### `yield` as an expression (`#phpExprYieldValue`)

PHP allows valueless `yield` in expression position (`$x = yield;`), not only as the statement `yield;`.

```antlr
| Op=T_YIELD ( (KeyValue=phpExprPrec T_DOUBLE_ARROW)? R=phpExprPrec )?      #phpExprYieldValue
```

| Source | Parse form | AST |
|--------|------------|-----|
| `yield $v` / `$x = yield $v` | `#phpExprYieldValue` with `R` | `PhpYieldAst` (value only) |
| `yield $k => $v` | `#phpExprYieldValue` with `KeyValue` + `R` | `PhpYieldAst` (key + value) |
| `$x = yield;` / `yield;` as a top expression | `#phpExprYieldValue` with no operand | prefix `PhpUnaryOpAst`, null operand |
| `yield;` via `innerStatementYield` | statement production | same unary AST |

### Tyhp `is` nullable RHS (`#phpExprBinaryOpGrammarAddon002Handler`)

`phpExprBinaryOpGrammarAddon002` is `T_TYHP_IS`. The handler allows an optional `?` immediately after `is` so `$x is ?T` parses. `$x is T ? a : b` is still ternary of `is` (`?` is not adjacent to `is`). PHP never takes this alternative (addon002 is the unreachable stub).

### `(void)` cast (`T_VOID_CAST`)

PHP 8.5 `(void)` is **not** a value-producing unary cast. Unlike `(int)` / `(string)` / … it is **not** in `phpExprUnaryPreOps`, so `$y = (void)$x` is a parse error. Forms (php-src):

| Form | Grammar | AST |
|------|---------|-----|
| Statement discard | `#statementVoidCast` — `T_VOID_CAST expr` in `statementRequiringTerminal` (semicolon via `statementTerminal`) | `PhpUnaryOpAst` prefix, op `T_VOID_CAST` |
| `for` init / update | `forExprItem` / `tyhpForInitExpr` — `T_VOID_CAST expr` inside `nonEmptyForExprs` / Tyhp init list | same unary AST |
| `for` condition | `forCondExprs` / `nonEmptyForCondExprs` — void cast only as a **non-final** item before a trailing plain `expr` (php-src `for_cond_exprs`) | same unary AST |

```antlr
| Op=T_VOID_CAST Expr=expr                                                  #statementVoidCast
| Statement=phpTopExpr                                                      #statementTopExpr
```

```antlr
forExprItem
    : Op=T_VOID_CAST Expr=expr                                              #forVoidCastExpr
    | Expr=expr                                                             #forPlainExpr
    ;

nonEmptyForCondExprs
    : (Items+=forExprItem T_SYM_COMMA)* Last=expr
    ;
```

Checker: operand is type-checked; cast type is `void` (non-value). `(void)` is the
intentional discard for `#[\NoDiscard]` (TYHP4165 suppressed).

**Emit rewrite** (`BuildVoidCastExpression`, Emitter §6c). Gate: `IsPhpVersionAtLeast(8, 5)`.

| Source | ≥ 8.5 (native) | &lt; 8.5 (lowered) |
| --- | --- | --- |
| `(void)$x;` | `(void) $x;` | `$x;` |
| `(void)\strlen($s);` | `(void) \strlen($s);` | `\strlen($s);` |
| for-list `(void)` items | native cast | omit cast; keep operand |

### Attributes on top-level `const` (`#attributedConstTopStatement`)

PHP 8.5 allows `#[…]` attributes on compile-time non-class `const` (php-src `attributed_top_statement` includes `T_CONST`). In `topStatementNoTerminal`:

```antlr
| Attributes=attributes Statement=attributedConstStatement                  #attributedConstTopStatement
| Attributes=attributes? Statement=attributedStatement                      #attributedTopStatement
…
| T_CONST ConstList=constList T_SYM_SEMICOLON                               #constDeclStmt
```

```antlr
attributedConstStatement
    : T_CONST ConstDecl=constDecl T_SYM_SEMICOLON
    ;
```

| Form | Grammar | Notes |
|------|---------|--------|
| `#[Attr] const X = 1;` | `#attributedConstTopStatement` → `attributedConstStatement` | Exactly **one** `constDecl`; attributes attach to the `PhpConstDeclListAst` |
| `const A = 1, B = 2;` | bare `#constDeclStmt` + `constList` | Multi-declarator still allowed **without** attributes |
| `#[Attr] const A = 1, B = 2;` | rejected | Grammar only accepts a single declarator when attributed (matches PHP: “Cannot apply attributes to multiple constants”) |

The attributed-const alternative is listed **before** the general `#attributedTopStatement` path so `#[…] const …` is not attempted as class/function/etc. Checker enforces `TARGET_CONSTANT` (existing TYHP4126/4127).

**Emit rewrite** (`EmitConstDeclaration`, Emitter §6f). Gate: `IsPhpVersionAtLeast(8, 5)` for top-level / namespace `const` only (class constants always keep attributes).

| Source | ≥ 8.5 (native) | &lt; 8.5 (lowered) |
| --- | --- | --- |
| `#[Attr] const X = 1;` | attributes attached before `const` | strip `#[…]` + TYHP5017; emit `const X = 1;` |
| class `#[Attr] const X = 1;` | always attach (PHP ≥ 8.0) | N/A |

### Emit rewrite matrix (summary)

Cross-cutting view of version-gated rewrites for the productions in this section. Full detail and ownership live in `Emitter/technical-guide.md` §6a–§6f.

| Feature | Native when | Lower-target rewrite |
| --- | --- | --- |
| Property-hook `#[…]` | ≥ 8.4 | Strip + TYHP5017 under hook polyfill |
| `exit` / `die` named + FCC | ≥ 8.4 | Positional / bare / static arrow |
| Pipe `\|\>` | ≥ 8.5 | Nested single-arg call chain |
| `(void) expr` | ≥ 8.5 | Omit cast; emit operand |
| `clone(…)` / clone-with / FCC | ≥ 8.5 | Unary / ObjectHelper / static arrow |
| Top-level `const` `#[…]` | ≥ 8.5 | Strip + TYHP5017; keep `const` |

## 8. Conventions

1. **Extend via addons first.** Prefer overriding a `*GrammarAddon` in `TyhpParser.g4` (or adding a Tyhp lexer token + mode rule) over rewriting large PHP rules.
2. **Mark overrides** with `// ! OVERRIDE` next to the rule.
3. **Gate Tyhp syntax** with `{this.isLanguageMode("tyhp")}?` unless the production must also apply in PHP mode (rare; usually belongs in `PhpParser.g4` only if it is shared PHP syntax).
4. **Contextual keywords** — when a word must remain a valid identifier in other positions, prefer fully-contextual `T_STRING` plus a parser predicate (`object`, `struct`, `hide`). When a dedicated token is required (`type` / `extension` / `async` / `operator` / `void` / `partial` / `extern` / `omit` / `deprecated` / `obsolete`, plus the hard language-mode words `await` / `parent` / `is` / `internal` / `with` / `using` / `typeof` / `nameof` / `variable_exists`), lex the word as `T_STRING` and reclassify it in `NextToken`. That includes the first token of a `${...}` interpolation, which enters scripting mode while the token is lexed. `(decimal)` and `:=` stay lexer rules with a language-mode predicate, because splitting them would change the PHP or tyhp token stream.
5. **Labels (`#ruleLabel`)** — visitors and generated `Visit*` methods key off these. Renaming a label is a breaking change for `Visitor/` and tests.
6. **Regions** — TyhpParser uses `//#region` / `//#endregion` for navigation (Root, Tyhpdef, Generics, Expressions, Identifiers, Statements, Functions, Objects, Types, …). Keep new rules in the matching region.
7. **Commit generated C#** with the `.g4` change. Reviewers should see both the grammar diff and the regenerated `Parser/` sources.
8. **Do not edit** generated recognizers, visitor contracts, `Tyhpdef*.GrammarMethods.cs`, or `Visitor/*.Included.cs` by hand; regen overwrites them. Edit the Tyhp partial or `Visitor/shared/*.inc`, then run `./compile_grammar.sh`.

## 9. Weirdness / why

### Addon placeholder token

`T_NO_GRAMMAR_ADDON_0000` exists so default addon alternatives are a real token match, not ε. That avoids silent empty alternatives that would change prediction. Nothing in the lexer ever emits this token for real source.

### Lexer mode addon for open tags

PHP’s `ST_CHECK_FOR_OTHER_OPEN_TAGS_LEXER_ADDON` is intentionally a stub that errors on any character. Tyhp fills that mode with `tyhp` / `tyhpdef` recognition. This keeps PHP open-tag scanning intact while allowing Tyhp tags after the same `<?` prefix.

### Parser mode is `"tyhp"` inside tyhpdef files

`tyhpdefBlock` and `tyhpdefTaglessSrcFile` assign parser `_languageMode = "tyhp"` even though `<?tyhpdef` sets lexer `_languageMode = "tyhpdef"`. Most Tyhp-mode addon predicates must fire for tyhpdef syntax (generics, modifiers, etc.). Tyhpdef-only lexer keywords still use lexer `_languageMode == "tyhpdef"`. `PhpParserAstVisitor.GetCurrentLanguageMode` returns `"tyhpdef"` for a `TyhpdefParser` block or tagless-file context and `""` for `TyhpdefParser.TyhpdefSrcFileContext`.

### Lexer-then-parser `compile_grammar.sh`

Each grammar pair compiles the lexer alone first so `tokenVocab` in `--lib` is the vocabulary just written, then compiles lexer and parser together. Moving `*.tokens` / `*.interp` out of `Parser/` keeps the Grammar folder as the vocabulary home. The temp directory is the `--lib` path; pointing `--lib` at `Grammar/` while the expanded files live elsewhere makes `tokenVocab` read a stale vocabulary.

### Ambiguity with `<` / `>`

Generics reuse comparison tokens. Several overrides exist specifically because statement prediction preferred expression/comparison alternatives over typed locals or `new` with type arguments. The C# lookahead helpers encode that design; do not remove the predicates without re-checking those cases.

### `>>` in operator overloads

`tyhpClassOperatorOverloadOp` matches `>>` as two `T_SYM_GT` tokens (`IsSR=T_SYM_GT`) **before** a bare `>`, so shift-right overloads do not steal the greater-than alternative.

### PHP short open tags disabled

`PhpLexer.g4` comments show short `<?` PHP tags disabled. Tyhp’s bare-`<?` path is for Tyhp/tyhpdef recognition via the addon mode, not for classic PHP short tags.

## 10. Pitfalls

1. **Forget `./compile_grammar.sh`** after `.g4` edits — `dotnet build` compiles stale generated sources.
2. **Edit only `PhpParser.g4` for Tyhp-only syntax** — PHP mode would accept it; put Tyhp-only behavior in Tyhp overrides gated by language mode.
3. **Hand-edit `Grammar/.antlr` Java** — irrelevant to the C# compiler.
4. **Add a grammar action without a matching partial method** — regen succeeds; C# build fails.
5. **Rename `#labels` without updating visitors** — silent wrong AST or missing overrides.
6. **Leave an addon as ε** — use `T_NO_GRAMMAR_ADDON_0000` / `noGrammarAddon` pattern for unused stubs.
7. **Assume parser `_languageMode` is `"tyhpdef"` inside a tyhpdef file** — `tyhpdefBlock` and `tyhpdefTaglessSrcFile` assign `"tyhp"`. Lexer `_languageMode` on `<?tyhpdef` is `"tyhpdef"`. `GetCurrentLanguageMode` returns `"tyhpdef"` for a `TyhpdefParser` block or tagless-file context. Tyhpdef-only keyword gating belongs on the lexer.
8. **Tagless + `?>`** — closing tags are not in the tagless entry follow set; also rejected via lexer `closeTagHandler` when `_taglessMode` is set (see lexer partial / Story 06 comments in the `.g4`).
9. **Alternative order** — left-recursive expression rules and addon placement matter; a Tyhp alternative lower in the rule may never win. Validate with real parse tests, not only “the tokens are accepted.”
10. **Tyhpdef hooked properties vs PHP `hookedProperty`** — tyhpdef must stay on `tyhpdefHookedProperty` / `tyhpdefPropertyHook` (semicolon bodies only; optional `?? expr` before `{`). Reusing `hookedProperty` would accept brace and `=>` bodies in `.tyhpdef`.

## 11. How to add new syntax (grammar side)

1. Decide whether the feature is Tyhp-only, tyhpdef-only, shared by `.tyhp` and `.tyhpdef`, or shared PHP.
2. Shared PHP lexing goes in `shared/PhpLexer.body.g4` (included by both lexers). Tyhp-only tokens and keywords go in `TyhpLexer.g4`. A keyword both languages lex goes in `shared/Tyhpdef.lexer-addons.g4` at the `#part` both lexers include.
3. A rule both parsers need goes in the matching `shared/*.g4` fragment, at the include both grammars already expand. A `.tyhp`-only rule stays in `TyhpParser.g4`. A tyhpdef file rule goes in `shared/Tyhpdef.rules.g4` (included by `TyhpdefParser` and, for the entries and class-body rules `.tyhp` shapes use, by `TyhpParser` as well). Prefer an existing `*GrammarAddon` override; add a new hook in `PhpParser.g4` only when no suitable extension point exists.
4. Gate Tyhp parser alternatives with `{this.isLanguageMode("tyhp")}?` and label them (`#tyhp…`). That predicate is true inside tyhpdef files because `tyhpdefBlock` / `tyhpdefTaglessSrcFile` assign parser `_languageMode = "tyhp"`.
5. Implement any new `{this.…}()` helpers on the Tyhp lexer/parser partials. Regeneration copies them onto `TyhpdefLexer` / `TyhpdefParser`.
6. Run `./compile_grammar.sh`, then update `Visitor/shared/` (emitted into both visitors) or the visitor that owns a one-parser rule, plus `Ast/`, binder/checker/emitter as needed.
7. Add parser/visitor tests under `tests/Tyhp.Tests/`.

Pipeline design principles for *which* syntax to invent live in `docs/content/intro_newSyntaxCreation.md`.
