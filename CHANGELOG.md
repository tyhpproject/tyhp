# Changelog

Notable changes to the Tyhp compiler, CLI, and language server. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added

- A class or enum may declare `operator default(): self` with no parameters. `default(ThatType)`, `default(self)`, and `default(static)` then have that type and call `ThatType::__tyhpDefault()`. A class or enum that does not declare the operator, including a subclass whose parent does, still produces null, and `default(self)` or `default(static)` there is typed as null to match. The call is not a constant expression when the operator is declared (TYHP4090). The body cannot use `$this` (TYHP4097). A return type other than `self` is TYHP4420, a parameter is TYHP4421, a second declaration is TYHP4422, and an interface, trait, abstract class, extension, or abstract operator is TYHP4423. A method named `__tyhpDefault` in any case is TYHP4426. A body that evaluates `default` of the same class is TYHP4424, including through an omitted constructor parameter whose default is that call (TYHP4425).
- `#[\Tyhp\InferGeneric]` on a generic function or method emits the value signature under the declared name and a `name__tyhpGeneric` companion stamped `layouts: [1]`. A bare call uses the plain method. A call with type arguments uses the companion. A type parameter no argument can supply is TYHP4407; a by-reference parameter is not a source. A parameter typed as the union `null|T|Promise<T>` supplies `T` (a promise contributes its result type, a plain value its own type, null nothing); a union with any other arm does not. The attribute on a declaration with no type parameters is TYHP4408, a warning. A non-erased generic without the attribute stays a layout-2 binder. An erased generic stays a plain method.
- A concrete generic class has `Class::new($T)($args)` and `Class::type($T)`. `new()` returns a closure that constructs the runtime class and uses the constructor's visibility. `type()` is public and returns `\Tyhp\Type` for that class. An abstract generic class has `type()` only. A generic child with fewer type parameters than its parent redeclares both with its own names and a trailing `mixed ...$__tyhpInherited`. A public `new()` inherited by a subclass refuses to build it when that subclass's constructor is not public. A method named `new` or `type` on a generic class, or on an ancestor, is TYHP4406.
- `lazy new Class(args)` and `lazy new Class<T>(args)` defer the constructor when `output.phpVersion` is 8.4 or newer and the class has a stored instance property. A generic class that Tyhp tracks at runtime also stores its type-argument bag, so it stays lazy, and its constructor still sees the type arguments. Arguments run immediately, in order, in the surrounding scope (locals, `$this`, `static`). On older targets, and when the class has no stored instance property, PHP would skip the constructor entirely, so the constructor runs immediately as an ordinary `new` (TYHP4403). An internal class other than `\stdClass`, a class that extends one, and a type that is not a class are TYHP4402. `lazy` is an identifier except immediately before `new`.
- `new Name[...]` checks that the name is a struct (TYHP4412). A spread into a struct initializer or a struct `with` list must be a struct (TYHP4414) whose fields the target declares (TYHP4415), whose field types are assignable, and whose array keys match, including aliases (TYHP4416). A second `with` after the brackets is TYHP4417.
- A spread in a struct initializer or a struct `with` list emits `\array_replace`, one argument per run, so integer array keys stay in place. With no spread, `new Name[...]` emits the same PHP as `new Name() with [...]`, and `new Name[]` emits the same PHP as `new Name()`.
- The language server completes unset struct fields inside `new Name[` and struct `with [` lists, required fields first, using the property name rather than an array-key alias. A field that a spread in the list already guarantees is not offered. Hover on a key shows that field's type and default, and those keys are colored as properties. `new Name() with [...]` on a struct can be rewritten to `new Name[...]`. TYHP4412 (`new SomeClass[...]`) has a quick fix that rewrites it to `new SomeClass() with [...]`.

### Changed

- `unset` of a local variable, a typed instance property, or a static property is TYHP4158. Assign `null` on a nullable declaration to drop the value. `#[\Tyhp\AllowUnset]` no longer exists and does not make `unset` legal. Unsetting an array element or an optional struct field stays allowed.
- A typed static property on a class, trait, or anonymous class must have an initializer (TYHP4418), including `?T` and `mixed`. `public static string $name = ''` and `public static ?string $name = null` are valid.
- After construction, every typed instance property must be initialized (TYHP4419). A declaration initializer counts even when a subclass replaces `__construct`. A promoted parameter counts only when the constructor that declares it runs. A subclass that declares `__construct` must call `parent::__construct` on every path that ends the constructor, including an early `return`, or assign the inherited property itself. A subclass that declares no constructor runs the parent constructor, and a gap inherited from it is reported once on the class that causes it. A class with no constructor that uses a trait with one runs the trait's constructor. A private ancestor property is named on the subclass constructor when that call is missing. A property introduced by a trait is checked on each class that uses the trait. A class that extends a tyhpdef type with no constructor is not asked to initialize that type's properties. An anonymous class is named `class@anonymous` in the diagnostic.
- An unkeyed entry in a struct initializer or a struct `with` list is an error (TYHP4413).
- TYHP4159 names the form that was written: `new Name[prop => value]` for a bracket initializer, `new Name() with [prop => value]` for `with`, and either form for a bare `new Name()`.
- A spread in a struct initializer or a struct `with` list counts as setting a required field when the source requires that field or gives it a default. A nullable source field with no default does not.
- A generic method or function that needs its type parameters at runtime is one PHP method under its declared name. That method takes each type parameter as `TypeLike|string|null` (default `null`) and returns a closure with the value signature (`Json::decode($T)($json)`). A null type argument is inferred on each call from a callable return, a class-string, or a value of that type parameter. An erased generic stays a plain method stamped `layouts: [1]`. A call to a layout-1 library method is still `name__tyhpGeneric(types)(args)`. Magic methods cannot declare type parameters (TYHP4404). A generic method cannot override or implement a non-generic method (TYHP4405).
- `nameof(...)` is a constant expression, so it can be an attribute argument. Attribute arguments are checked against the constructor, including `#[Name<T>(...)]`. `nameof(Type::$prop)` has type `__PropertyName<Type>` and is rejected when that member is not declared (TYHP4101) or belongs to a different type (TYHP4010); a string literal satisfies a `__PropertyName<Type>` parameter only when it names a property of `Type` (TYHP4101). A lambda in an attribute is still TYHP4090. `T::class` on a generic parameter is `__ClassName<T>` and emits that parameter's class name.
- `using`, `using await`, and a `:=` local disposed from `try`/`finally` call `dispose()` or `disposeAsync()` only when the value is not an uninitialized lazy object, so it is not initialized just to be disposed. The emitted guard calls `ReflectionClass::isUninitializedLazyObject` (behind `\PHP_VERSION_ID >= 80400` when `output.phpVersion` is below 8.4) and needs no package beyond the disposable contracts.
- Emit and checking are much faster in projects that load large tyhpdef packages. A PHP 8.5 build of `tyhp/rhetoric` emits in about 8 seconds instead of about 150 and checks in about 4 seconds instead of about 13, with identical output and diagnostics.
- An `Expression` or `PropertyPath` parameter is emitted as `Expression|\Closure` or `PropertyPath|\Closure`. The value body starts by calling `fromClosure` when the argument is a `\Closure`, including the value closure of a layout-2 generic function or method after its type arguments are inferred. A promoted constructor parameter, a by-reference or variadic parameter, a property hook parameter, an inline closure's parameter, and `#[\Tyhp\PhpType]` keep the spelled type. An inline `fn` is still emitted as a fluent `backedBy` chain.

### Fixed

- A property hook may read a typed property that the constructor initializes on every path without a possibly-uninitialized error (TYHP4157). A property the constructor assigns on only some paths, or never, is still TYHP4157 in the hook. A constructor access to a hooked property (`$this->hooked` read or assignment) or a promoted `set` hook, which runs the hook during construction, is TYHP4157 when the hook reads a property that is not yet initialized at that point.
- A property default, class constant, or enum case value must be a constant expression PHP can load (TYHP4090). `new` there is rejected, including `new` nested in an array or a conditional; construct the object in the constructor. `new` is still accepted in a parameter default (including a promoted parameter), a `static` variable initializer, a global constant, and an attribute argument. A struct initializer without a spread (`new Name[]`, `new Name[k => v]`) can still initialize a property, because it emits an array. `clone`, `static::`, `instanceof` / `is`, `|>`, `@`, `(decimal)`, `++` / `--`, a struct initializer spread, and `$var::NAME` are the same diagnostic in a property default, a class constant, an enum case value, a parameter default, and an attribute argument.
- A library property default written as `new Name[...]` is copied into `package.tyhpdef` in that form.
- TYHP4412 suggests `new Name() with [...]` only when that name is a class that can be constructed. A type alias, interface, enum, trait, object shape, or abstract class does not get that suggestion, and the language server does not offer the rewrite.
- A field of a struct stored on a class property, including a promoted constructor parameter, is read with array access (`$this->point['x']`). The property itself stays `$this->point`.
- A type alias is expanded in the namespace that declared it. A union of structs used from another namespace keeps those structs, so a field every arm declares (`$value->ok`) type-checks and is read as that array key when every arm is a struct that stores the field under the same key. A union that includes a class, or arms with different keys, reads the property (`->`). Comparing a field to a string literal (`$node->kind === 'scalar'`) keeps the arms that can hold that literal, and the other fields then use that arm's type.
- An `async` `#[\Tyhp\InferGeneric]` function or method whose return type names one of its type parameters stamps that bound type on the Promise. The inner closure's PHP return hint no longer replaces it with `mixed` or a bare `array`. A union of those parameters stays one type when every member is the same type.
- A generic class freezes each type argument with `->immutable()` before registering a property type. A nullable property (`?T`) no longer marks the type argument itself nullable.
- `\Closure::bind` accepts a closure whose `$this` and scope are already known, the same way `$closure->bindTo` does. The closure argument is no longer rejected as not assignable to `\Closure<mixed, mixed, mixed>` (TYHP4010).
- A class, trait, or enum method with `#[\Tyhp\Php]` that holds for only some PHP versions at or above `output.phpVersion` is emitted inside `\PHP_VERSION_ID`, and every such sibling stays in `package.tyhpdef`. This includes a generic method that reads its type argument at runtime (each sibling's body goes inside that method's closure, and every sibling gets the same `#[\Tyhp\GenericRuntime]` stamp) and an `async` method. A method that holds for no version at or above the floor is still omitted. Functions and types still compile only the declaration that matches the floor.
- An object `with` list rejects an unkeyed entry (TYHP4409). A spread is accepted only when the source is a struct and each field's array key names a property of the target, including an alias and a property inherited through `extends` (TYHP4410, TYHP4411). The field type must be assignable, readonly properties use the same checks as a keyed entry, and a later entry overrides an earlier one.
- An inline `fn` or `function` passed to a callable parameter is rejected when its explicit return type is incompatible with that parameter's return type (TYHP4010).
- A named argument whose label matches an in-scope class is emitted as that label (`column: $column`), not as the class name. An inlined extension method or operator body keeps member names (`$h->column`, `Holder::column()`) the same way instead of qualifying them as an imported class.
- Generated generic construction helpers (`new_<Mangled>__tyhpGeneric` and `new_<Mangled>__tyhpLazy`) use the constructor's visibility. A private constructor emits a private helper, and a protected constructor emits a protected helper.

- A first-class callable of a generic method or function that needs its type parameters at runtime (`f<int>(...)`, or `$x |> f(...)` below PHP 8.5) is the callable itself. It was the binder, so calling it returned another closure. `f<int>(...)` on a library method stamped `layouts: [1]` keeps its type arguments: it is `f__tyhpGeneric(\Tyhp\Type::int())`, the closure with `int` already bound, where it used to drop `<int>`.
- A generic callable's per-call type inference handles a variadic `T ...$rest` (one type per element, not `array`) and a `callable`, class-name, or `T` parameter that allows `null` (a `null` argument is skipped instead of throwing a `TypeError`).

- A class used as a parameter, return, or property type is no longer emitted as `array` when a struct with the same short name is declared in another namespace.

- `Class::name()` resolves to the static method or `__callStatic` fallback even when the class also declares a constant spelled `name`. The call is typed from the method, not as `mixed` from the constant (`Type::int()` beside `Type::int`).

- An extension method call inside an expression-tree lambda stays a method call (`$title->startsWith($prefix)` is a `MethodCallExpression`). The extension body is not substituted into the tree. `compile()` still runs that body.
- A `mixed` type argument in a `.tyhpdef` satisfies an `extends` bound, so a signature that spells `Builder<mixed>` from a PHPDoc `Builder<*>` can be called. The same argument written in a `.tyhp` file is still checked.
- A value passed to a parameter typed as an extern unioned with a real type (`\SortDirection|string`) is not a use of the extern when the value fits the real arm. A value that needs the extern arm still reports TYHP4307.
- Attributes on a class or function in a namespaced file resolve the names in their arguments through that file's namespace and imports, so `#[Index<Post>([nameof(Post::$title)])] class Post {}` type-checks `Post` instead of reporting TYHP4090 or skipping the check.
- `array<'get'|'set', T>` and `array<0|1, T>` type-check. String and int literal types, including unions of them, satisfy the array key constraint.
- The language server's memory no longer grows to many gigabytes over a long session. It reuses parsed tyhpdef packages across analysis passes instead of reloading them on every edit. It also returns freed memory to the OS after 5 seconds of idle.
- The language server no longer keeps every earlier analysis pass alive while you edit, which grew memory by tens of megabytes per edit and by hundreds when tyhpdef files changed. Files that were not re-parsed also no longer resolve names against symbols from a previous pass.
- The language server watches the directory that holds `tyhp.json` and the project's sources, not the whole editor workspace. Files outside the project's `include`/`exclude` globs no longer enter analysis, and disk changes to unrelated files no longer trigger a re-check. Edits to `.tyhpdef` files and to `composer.json`/`composer.lock` reload the tyhpdef packages.

## [805.1.2-beta.4] - 2026-11-04

### Added

- Emitted PHP includes PHPStan/Psalm docblock tags (`@param`, `@return`, `@var`, `@template`, `@extends`, `@implements`, `@internal`) where the PHP declaration drops type information. `emit.docblocks` defaults to `lossy-only` in every build profile; `all` emits a tag for every signature type and `off` emits none. `emit.docblockDialect` defaults to `both`. Author docblocks and emitter directives are kept; `output.comments: false` drops prose and keeps analysis tags.
- In a `.tyhp` file, `<?=` is a Tyhp echo. The expression list is parsed and checked as Tyhp (`is`, `typeof`, `with`, and `nameof` are keywords) and emitted as `echo`, with the same stringable rules as `echo` (TYHP4120). The output is not escaped. A `.php` file still treats `<?=` as a PHP echo.
- Expression trees accept nested arrow `fn` bodies (as `LambdaExpression` nodes), list and keyed array literals, and `?->` method calls. Array spread is rejected with TYHP4322.
- `PropertyPath<callable(T): R>` parameters infer a generic `R` from an inline `fn`, also in a union with `callable(T): R`; a `?->` chain makes `R` nullable.
- Emitted properties and promoted constructor parameters whose PHP hint loses type information (type arguments, struct types, source type aliases) carry `#[\Tyhp\PropertyType('…')]`, which `\Tyhp\Type::fromProperty()` reads.
- Expression-tree parameter nodes carry the full declared type (`App\Table<App\Blog>`, `struct App\Address`) instead of the erased class name.
- More narrowing forms: `\assert($cond);`, loose `!= null` / `<>` / `== null` (non-null side only), nested property paths (`$a->b->c`), static properties of any class, and `switch (true)` / `match (true)` arms, which see earlier conditions as false.
- Template string holes can name type aliases (imported, namespace-qualified, class-level, generic, or from a tyhpdef), so template aliases compose. An unknown hole name reports TYHP3003 and a self-referencing alias TYHP3029.
- A double-quoted interpolation whose text and hole types fit a template string type is assignable to it, so `"api/{$resource}/items"` can be returned as `"api/${string}/items"`.
- Type parameters constrained to stringable types (`T extends string`, `T extends 'a'|'b'`) can be interpolated, concatenated, echoed, and used as template holes.

### Changed

- New error TYHP4198 for reading or writing a property, calling a method, or indexing through a possibly null receiver without narrowing it first. Code that compiled before may now fail; narrow the value or use `?->`.
- A value read through `?->` is nullable (`$a?->b` is `?B`), so using it where a non-null value is required now reports an error. Later links in the same chain short-circuit as in PHP.
- Expression trees reject a variable method name (`$x->$m()`), a class held in a variable (`new $c()`, `$c::make()`, `$x::class`), named arguments, and argument unpacking with TYHP4322. These were accepted before and emitted incorrectly.
- New error TYHP4199 for a template string hole with no string form (`${bool}`, `${array}`) or written as an expression (`${$x}`, an inline nested template).
- `.` and `.=` report TYHP4120 for operands with no string form, such as arrays and unconstrained type parameters. Nullable stringable operands are allowed.
- String interpolation, heredoc holes, `echo`, and `print` accept nullable stringable values (`?string`, `?int`, a nullable class with `__toString`), like `.` does; `null` becomes `''`. In a template string type, a nullable hole fits only a hole that also allows empty text, so `"item-{$id}"` with `?int $id` fits `"item-${''|int}"` but not `"item-${int}"`.
- `${int}` and `${float}` template holes match only the text PHP's `(string)` cast produces: `${int}` accepts `'3'` but not `'03'` or `'+3'`.
- `break` inside a closure that is nested in a loop is now rejected.
- New error TYHP4378 for a default value on a readonly property (or any instance property of a `readonly class`) when `output.phpVersion` is below 8.6, which PHP rejects when the class loads. Assign the value in the constructor or use a promoted parameter default.
- TYHP4024 now reports every magic method PHP rejects on an enum (`__toString`, `__get`, `__set`, `__isset`, `__unset`, `__destruct`, `__clone`, `__serialize`, `__unserialize`, `__sleep`, `__wakeup`, `__set_state`), not just `__construct`, and names the method.
- New error TYHP4379 for `__debugInfo()` on an enum when `output.phpVersion` is below 8.6.
- With `build.updateComposer`, a target PHP version that has no published `tyhp/*` runtime release (such as `8.0` or `8.1`) reports TYHP7108 and leaves `composer.json` unchanged, instead of pinning `804.X.Y` packages that need PHP 8.4.
- `scripts/release.sh` takes `prerelease`, `alpha`, `beta`, `rc`, `release`, `patch`, `minor`, `major`, or an explicit `X.Y.Z`. It publishes the GitHub Release only after each asset matches `dist/checksums.txt`, and it checks the bundled runtime versions against the runtime checkout.
- Every instance property and promoted constructor parameter of a `readonly class` is now readonly, as in PHP, so all readonly checks apply to it: writing it through another object or from outside the class (TYHP4021), a hook on it (TYHP4155), and `with` on it (TYHP4139–TYHP4141, TYHP4400, TYHP4401).
- TYHP4021 now also reports writes to a readonly property from a function, the file scope, or a class other than the declaring class or a subclass. Properties with an explicit set visibility such as `public(set)` are not reported.
- New error TYHP4109 for a static property in a `readonly class`, which PHP rejects when the class loads.

### Fixed

- A runtime-tracked generic `readonly class` emits an instance `\Tyhp\GenericObject $__tyhpGeneric` property with no default, initialized by `__bootGenericBag__tyhpGeneric()`, instead of the `HasGenerics` trait, so the class loads on PHP 8.2 and later and `clone` keeps the tracked types. A generic class that is not readonly still uses the trait.
- Readonly `new … with` below PHP 8.3 reports TYHP4400 instead of emitting a `__clone` wrapper that PHP 8.2 rejects. `clone … with` on a `readonly class` below PHP 8.5 reports TYHP4401. Experimental `clone … with` on PHP 8.3–8.4, for a class that is not readonly, emits a wrapper that loads: the empty constructor has no return type, it does not call the parent constructor with no arguments, and overrides sit on a static stack.
- Inline HTML and `<?=` echoes in a `.tyhp` file stay in source order, including inside a function or control-flow block, and a later `<?tyhp` section is accepted. `<?tyhp ?>` or `<?tyhp?>` opens an empty section. A `<?php` block in a `.tyhp` file reports TYHP2005. In a tagless project, the first six characters choose the file: `<?tyhp` is a tagged template, and any other `.tyhp` file is tagless code with no open tag, so `<?tyhp` there is not accepted.
- Inline HTML in a `.tyhp` file is emitted exactly as written: the emitted PHP no longer indents HTML lines (which printed extra spaces, including inside closures), and a blank line right after `?>` is kept.
- An `fn` the emitter could not turn into an expression tree was silently emitted as a plain closure; it now reports TYHP5024.
- `$a ?: $b` in an expression tree emitted a `null` true branch, and a nested `fn` passed to a `PropertyPath` parameter inside a tree was emitted as a plain closure.
- A `switch` with a `default` case where every case returns or throws no longer reports TYHP4011, and code after it reports TYHP4012.
- `break 2` / `continue 2` from a `switch` inside a loop no longer reports TYHP4026, and a loop's exit now accounts for the state at each `break` and `continue`.
- An `if` arm that returns, throws, breaks, or continues now leaves only the other arm's narrowing after the `if`, and a write to a narrowed path inside a nested block ends that narrowing.
- `<>` was typed `unresolved` (TYHP4043); it now works like `!=`.
- `EventLoop::run` accepts a `Promise<void>`, so an `async` function declared `: void` can be run from synchronous code.
- Extension methods on a union target resolve when called from inside a namespace.
- A `catch` that always throws or returns no longer makes locals assigned in the `try` "possibly undefined" (TYHP4014).
- `\get_object_vars()` on a concrete object no longer reports TYHP4035.
- Generated tyhpdefs keep a template string type's pattern and fully qualify alias names in its holes, so a library's consumers see the same type.
- A property or promoted constructor parameter in a `readonly class` without its own `readonly` no longer reports TYHP4108, which is retired.
- `new … with` on a `readonly class` on PHP 8.3–8.4 emits `new readonly class`, because a non-readonly class cannot extend a readonly class.
- Concatenating a nullable class that has `__toString` (`?Name . 'x'`) no longer reports TYHP4029.
- `tyhp --explain` has long-form text again for about 20 codes (including TYHP3031–TYHP3035 and TYHP4373–TYHP4377), and keeps Markdown list items on separate lines.
- When `build.updateComposer` cannot read a runtime package's own `composer.json`, it pins `tyhp/*` `0.4` (`80N.0.4`) and `tyhpdef/php` `0.0.3` instead of `0.1` and `0.0.1`.
- A `readonly class` that uses a trait with a non-readonly instance property or a static property now reports TYHP4380 when `output.phpVersion` is 8.2 or newer. PHP rejects that class when it loads.
